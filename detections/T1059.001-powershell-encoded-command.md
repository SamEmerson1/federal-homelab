## Hypothesis

`powershell.exe -EncodedCommand <base64>` runs a Base64-encoded script without it ever appearing
in plain text on the command line. It is a staple of loaders and living-off-the-land activity,
because it defeats casual command-line inspection and simple keyword filters. Legitimate software
occasionally uses encoded commands, but on a workstation an interactive user launching one is
unusual and worth review.

Windows records the launch as Security event 4688 (with command-line auditing enabled), so the
encoded flag and its argument are visible there. PowerShell script-block logging (event 4104)
records the *decoded* script separately, which is what confirms what actually ran.

## Detection logic

```spl
index=lab_win source="XmlWinEventLog:Security" EventCode=4688
    (NewProcessName="*\\powershell.exe" OR NewProcessName="*\\pwsh.exe")
| regex CommandLine="(?i)\s[-/](e|ec|en(c(o(d(e(d(c(o(m(m(a(n(d)?)?)?)?)?)?)?)?)?)?)?)?)\s+[A-Za-z0-9+/=]{16,}"
| table _time host SubjectUserName ParentProcessName NewProcessName CommandLine
```

PowerShell accepts any unambiguous abbreviation of `-EncodedCommand` (`-e`, `-en`, `-enc`, …), so
the pattern matches the flag at any length, followed by a Base64 string of at least 16 characters.
It also accepts the `/` switch form. Confirming what ran uses 4104:

```spl
index=lab_win source="XmlWinEventLog:Microsoft-Windows-PowerShell/Operational" EventCode=4104
| table _time host ScriptBlockText
```

## False positives

| Scenario | Likelihood | Tuning |
|---|---|---|
| Management tooling running encoded commands | Medium in production | Allowlist the parent process or the service account |
| Software installers using encoded bootstrap commands | Low–medium | Allowlist by parent image after a baseline |
| Administrator pasting an encoded one-liner | Low | Correlate with the 4104 decoded content before escalating |

## Response guidance

1. Pull the matching 4104 event and read the decoded script.
2. Check the parent process — an Office app or a browser launching encoded PowerShell is far more
   serious than a console session.
3. Look for network connections (Sysmon event 3) from the PowerShell process.
4. If unexplained: isolate the host, preserve the script-block content, and pivot to the parent
   process tree.

## Gaps

- Encoding is only one launch style. Download cradles (`IEX (New-Object Net.WebClient)...`),
  `-Command` with obfuscation, and fileless execution are separate cases; script-block logging
  (4104) is the backstop that captures them regardless of launch flags.
- PowerShell version 2, if present, does not write 4104. Not applicable on WS01.
