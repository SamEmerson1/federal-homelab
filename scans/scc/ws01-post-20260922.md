## Method

Remediation was applied in reviewed passes with a snapshot before each, and measured by a full
rescan after each pass, under identical tool, benchmark, profile, and scoring conditions. Working
scan outputs from the intermediate passes were retained locally; only the baseline and the final
result are committed here, so that every figure in this repository corresponds to one published
report.

The scan account changed between baseline and final. The baseline ran as a local administrator;
the final scan ran as `LAB\stigadmin`, a domain account in WS01's local Administrators group. This
is a deliberate, documented deviation from identical-conditions rescanning: several STIG rules
evaluate user-scope policy, and a local account provably cannot receive user Group Policy in this
domain. Scanning as a local account would have reported failures that reflect the account rather
than the machine. Reasoning in [`docs/ws01-stig-gpo.md`](../../docs/ws01-stig-gpo.md).

## Remaining failures

Seven rules remain open. Three have no remediation path in this environment; four require
certificate content newer than the current release of the DoD distribution tool provides.

| Rule | STIG ID | CAT | Finding | Why open |
|---|---|---|---|---|
| V-253370 | WN11-CC-000075 | I | Credential Guard must be running | Windows 11 Enterprise/Education feature. Not available on Pro |
| V-253254 | WN11-00-000005 | II | Domain-joined systems must run Windows 11 Enterprise | Licensing. Drives V-253370 |
| V-253470 | WN11-SO-000251 | II | Multifactor authentication for local and network access | Requires DoD CAC/PIV infrastructure, middleware, and a card reader |
| V-253427 | WN11-PK-000005 | II | DoD Root CA certificates in the Trusted Root store | DoD Root CA 3, 4, and 5 are installed. The rule requires 3, 5, and **6** by thumbprint; Root CA 6 is absent from the tool payload used |
| V-253428 | WN11-PK-000010 | II | External Root CA certificates in the Trusted Root store | ECA roots not present in the payload installed |
| V-253429 | WN11-PK-000015 | II | DoD Interoperability cross-certificates in the Untrusted store | Two cross-certificates are installed, but the rule tests a specific certificate by thumbprint that the payload does not contain |
| V-253430 | WN11-PK-000020 | II | US DoD CCEB Interoperability cross-certificates in the Untrusted store | As above |

### On the four certificate findings

DoD certificates were introduced through InstallRoot 5.6, the current NIPR release, transferred into
the isolated segment and verified by SHA-256 and Authenticode signature before execution. The tool
placed DoD Root CA 3, 4, and 5 plus 45 intermediates and two Interoperability cross-certificates.

STIG V2R10 tests these rules against specific certificate thumbprints, and the set it expects is
newer than the trust-anchor payload shipped with InstallRoot 5.6. This is a version gap between the
distribution tool and the benchmark, not a configuration error on the host. Remediation is to source
the current PKCS#7 bundles directly from the DoD Cyber Exchange rather than relying on the tool
payload; recorded in the POA&M.
